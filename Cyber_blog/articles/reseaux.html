Comprendre les ports réseau

Un port est une porte logique : c'est par elle qu'un service accepte ou refuse une connexion. Apprendre à lire les ports d'une machine, c'est déjà apprendre à lire une partie de son niveau de sécurité.

Une adresse IP ne suffit pas

Une adresse IP identifie une machine sur un réseau, mais pas le programme à qui les données sont destinées. Un serveur peut à la fois héberger un site web, un serveur de messagerie et un accès distant. Pour les distinguer, on utilise des ports : un numéro codé sur 16 bits, donc compris entre 0 et 65535.

La combinaison IP:port désigne donc un service précis. Par exemple, 192.168.1.10:443 pointe vers le service web sécurisé de la machine 192.168.1.10.

TCP et UDP : deux transports, deux usages

  • TCP : orienté connexion, il vérifie que les données arrivent complètes et dans le bon ordre. Utilisé par le web, la messagerie et SSH.
  • UDP : sans connexion, plus rapide mais sans garantie de livraison. Utilisé par le DNS, le streaming et les jeux en ligne.

Un même numéro de port peut être utilisé en TCP et en UDP en même temps : chaque protocole possède son propre espace de ports.

Les ports que tout débutant doit connaître

  • 20 / 21 — FTP, transfert de fichiers non chiffré
  • 22 — SSH, administration à distance chiffrée
  • 25 / 587 — SMTP, envoi d'e-mails
  • 53 — DNS, résolution de noms
  • 80 — HTTP, web non chiffré
  • 443 — HTTPS, web chiffré
  • 3306 — MySQL, base de données
  • 3389 — RDP, bureau à distance Windows
À retenir : les ports 0 à 1023 sont dits « bien connus » et réservés aux services standards. Utiliser un port inhabituel n'apporte pas de vraie sécurité : c'est de la discrétion, pas de la protection.

Voir les ports ouverts sur ta propre machine

Sur Linux, la commande ss liste les ports en écoute. À exécuter uniquement sur ton propre système : 

ss -tulpn
  • -t : sockets TCP
  • -u : sockets UDP
  • -l : uniquement les ports en écoute
  • -p : le programme associé
  • -n : afficher les numéros au lieu des noms

L'adresse 127.0.0.1 signifie que le service n'est accessible que depuis la machine elle-même, tandis que 0.0.0.0 indique une écoute sur toutes les interfaces, donc potentiellement depuis le réseau.

Pourquoi c'est un enjeu de sécurité

Chaque port ouvert est une surface d'attaque. Un service obsolète, mal configuré ou protégé par un mot de passe par défaut peut devenir la porte d'entrée d'une intrusion. La règle est simple : un service dont on n'a pas besoin ne doit pas être exposé.

  • Fermer ou désactiver les services inutilisés.
  • Limiter l'écoute à 127.0.0.1 quand c'est possible.
  • Filtrer les ports entrants avec un pare-feu.
  • Mettre à jour régulièrement les services exposés.
  • Ne jamais exposer directement une base de données à Internet.
⚠ Rappel légal : scanner les ports d'une machine qui ne t'appartient pas est illégal. Entraîne-toi sur ta propre machine virtuelle ou sur une plateforme de laboratoire dédiée.

À retenir

  • Un port identifie un service sur une machine.
  • TCP est fiable, UDP est rapide : les usages diffèrent.
  • Connaître les ports courants aide à repérer une anomalie.
  • Réduire les ports ouverts, c'est réduire la surface d'attaque.
