DÉFENSE • 7 MIN DE LECTURE

Le pare-feu (firewall) expliqué simplement

Un pare-feu est souvent la première barrière qu'un attaquant rencontre. Comprendre comment il prend ses décisions permet de le configurer sans l'ouvrir inutilement — et sans croire qu'il protège de tout.

Ce qu'est un pare-feu

Un pare-feu (firewall) est un filtre placé sur le chemin du trafic réseau. Son rôle : autoriser, bloquer ou journaliser les communications selon un ensemble de règles. C'est la brique de base de toute défense périmétrique.

Il travaille en général sur le couple adresse IP / port / protocole. Par exemple : « j'autorise les connexions vers le port 443 depuis Internet, mais je bloque tout le reste ».

Trois grandes familles

  • Pare-feu réseau : protège un réseau complet. C'est le cas des routeurs ou des appliances dédiées.
  • Pare-feu local : installé sur une machine et filtre son propre trafic, entrant comme sortant.
  • Pare-feu applicatif (WAF) : analyse le contenu des requêtes web pour bloquer les attaques applicatives, comme les injections.

Deux logiques de filtrage

Le filtrage statique

Les règles sont définies à l'avance et ne changent pas. Simple et rapide, mais il ne tient pas compte de l'état de la connexion. Pour chaque paquet, il réévalue toutes les règles, ce qui oblige à en ouvrir des deux côtés.

Le filtrage dynamique (avec état)

Le pare-feu suit l'état des connexions. Si une session sortante est autorisée, les réponses entrantes le sont automatiquement le temps de cette session. C'est la logique utilisée par les pare-feux modernes.

Un exemple de règle

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw enable

Ce jeu de règles bloques tout le trafic entrant par défaut, puis n'ouvre que SSH (22) et HTTPS (443). Ce principe s'appelle le refus par défaut : on autorise explicitement ce dont on a besoin, jamais l'inverse.

Principe de moindre privilège : une règle doit autoriser le strict nécessaire. « Tout ouvrir pour être sûr que ça marche » est exactement l'erreur à éviter.

Ce qu'un pare-feu ne fait pas

  • Il ne protège pas d'une attaque venue de l'intérieur.
  • Il ne corrige pas une application vulnérable.
  • Il n'empêche pas un utilisateur de cliquer sur un lien piégé.
  • Il ne remplace pas la mise à jour des logiciels.

Le pare-feu est une couche dans une stratégie globale. La sécurité en profondeur consiste à superposer les défenses plutôt qu'à tout miser sur une seule.

Bonne pratique : journaliser

Les journaux du pare-feu racontent l'histoire des tentatives de connexion. Les consulter permet de repérer un scan réseau ou une tentative répétée sur un même port. 

sudo tail -f /var/log/ufw.log

À retenir

  • Le pare-feu filtre le trafic selon IP, port et protocole.
  • Le refus par défaut est la posture la plus sûre.
  • Un pare-feu complète les autres défenses, il ne les remplace pas.
  • Les logs sont une source d'information précieuse.
