NIVEAU : DÉBUTANT

Capturer du trafic avec Wireshark

Objectif : observer ce qui circule réellement sur le réseau, comprendre une poignée de main TCP et apprendre à filtrer le trafic pour isoler une communication précise.

DURÉE 40 minutes
OUTILS Wireshark, curl
PRÉREQUIS Article « Comprendre les ports réseau »

⚠ Cadre de l'exercice

À lire avant de commencer : ne capture jamais le trafic d'un réseau qui ne t'appartient pas. Une capture peut contenir des identifiants, des cookies et des données personnelles. Travaille sur ta machine, sur ta machine virtuelle ou sur un réseau de laboratoire isolé.

Étape 1 — Installer Wireshark

sudo apt update
sudo apt install wireshark

Ajoute ensuite ton compte au groupe wireshark pour pouvoir capturer sans être root, puis reconnecte-toi : 

sudo usermod -aG wireshark $USER

Étape 2 — Choisir l'interface

Lance Wireshark et repère les interfaces disponibles. Sur Linux, l'interface principale est souvent eth0 (Ethernet) ou wlan0 (Wi-Fi).

Sélectionne-la puis démarre la capture avec le bouton bleu. Wireshark enregistre désormais tout le trafic qui passe par cette interface.

Étape 3 — Générer du trafic volontaire

Pour avoir quelque chose à observer, ouvre un second terminal et envoie une requête vers un site : 

curl -I https://example.com

De retour dans Wireshark, clique sur le bouton rouge pour arrêter la capture. Tu disposes maintenant d'un enregistrement complet de cette session.

Étape 4 — Filtrer le trafic

Sans filtre, la liste est illisible. La barre de filtre accepte une syntaxe précise : 

ip.addr == 93.184.216.34
tcp.port == 443
dns
http.request
  • ip.addr == : se limiter à une adresse IP.
  • tcp.port == : isoler un port précis.
  • dns : n'afficher que les requêtes DNS.
  • http.request : uniquement les requêtes HTTP.
Astuce : fais un clic droit sur un paquet puis « Appliquer comme filtre » pour générer le filtre automatiquement. C'est le moyen le plus rapide d'apprendre la syntaxe.

Étape 5 — Lire une poignée de main TCP

Filtre sur un port, puis observe le tout début de la communication. Tu verras trois paquets caractéristiques :

  • SYN : le client demande une connexion.
  • SYN/ACK : le serveur accepte.
  • ACK : le client confirme.

Question 1 : combien de temps s'écoule entre le SYN et le SYN/ACK ? Cette durée correspond au temps de réponse du serveur.

Étape 6 — Suivre un flux complet

Clic droit sur un paquet TCP puis « Suivre le flux TCP ». Une fenêtre affiche la conversation complète, avec les données échangées.

Question 2 : sur une connexion HTTPS, le contenu est-il lisible ? Tu dois constater que non : le chiffrement TLS protège les données. En revanche, les adresses IP et les ports restent visibles, car ils servent au routage.

Étape 7 — Repérer ce qui sort de l'ordinaire

En analyse défensive, on cherche l'anomalie. Quelques pistes : 

tcp.flags.syn == 1 && tcp.flags.ack == 0
  • Un nom de domaine au hasard excessif peut indiquer un canal caché.
  • Des SYN en rafale vers de nombreux ports trahissent un scan.
  • De gros volumes vers une adresse inhabituelle évoquent une exfiltration.
⚠ Rappel : une capture contient souvent des données personnelles. Supprime tes fichiers .pcap après le lab et ne les partage jamais sans anonymisation.

Synthèse du lab

Ce que tu as appris

  1. Capturer le trafic d'une interface réseau.
  2. Écrire des filtres d'affichage précis.
  3. Reconnaître une poignée de main TCP.
  4. Suivre un flux et constater l'effet du chiffrement TLS.
  5. Adopter une démarche d'analyse : chercher l'anomalie.

Questions de validation

  • Quelle différence entre une capture filaire et sans fil ?
  • Pourquoi un filtre d'affichage ne modifie-t-il pas la capture ?
  • Un analyseur peut-il lire le contenu d'un flux HTTPS ?
  • Pourquoi anonymiser une capture avant de la partager ?
